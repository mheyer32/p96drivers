# m68k register-parameter attribute tests

Standalone probe suite for **bebbo `m68k-amigaos-gcc` / `m68k-amigaos-g++`**, matching Picasso96 `boardinfo.h` `__REGD*` / `__REGA*` macros and `-mregparm=4` build flags used in p96drivers.

## Why

Picasso96 passes BoardInfo hook arguments in fixed 68000 registers (`__REGA0`, `__REGD7`, …). Older bebbo **g++** silently ignored `__asm("dN")` on enum-typed parameters (`-Wattributes`: *"ignoring attributes applied to 'RGBFTYPE' after definition"*), so callees read the wrong register (e.g. `CalculateBytesPerRow` saw format `0` from `d2` instead of `d7`).

**Fixed** in local `amiga-gcc` (6.5) and `amiga-gcc-13` (13.2): C++ now attaches `asmreg` via a type-variant copy (same idea as C’s `push_parm_decl`), not through `build_type_attribute_qual_variant`.

Production code may still use `ULONG` (`RGBFTYPE_REG` in `common.h`) for compatibility with unfixed toolchains. This directory locks register behaviour with objdump inspection and optional Amiga runtime checks.

## Quick start (host objdump — primary check)

```sh
source ~/bin/startAmigaGCC.sh
cd tests/regparm_asm
make check
```

This generates probe functions, cross-compiles C and C++ objects, disassembles them, and prints a matrix like:

```
LANG REG  TYPE         VARIANT            STATUS       DETAIL
c    d7   enum         single             OK           reads d7 (direct)
cxx  d7   enum         calc_bpr           KNOWN_FAIL   reads d2, expected d7; g++ enum attribute bug
cxx  d7   ulong        calc_bpr           OK           reads d7 (direct)
...
```

Exit status is **0** if there are no *unexpected* failures. `KNOWN_FAIL` and `SKIP` rows do not fail the build.

### Without `-mregparm=4` (contrast)

```sh
make check-norp
```

## Coverage

| Area | Details |
|------|---------|
| Data regs | `d0`–`d7` |
| Address regs | `a0`–`a6` (see a4/a5 notes below) |
| Types (data) | `ULONG`, `LONG`, `UWORD`, `WORD`, `UBYTE`, `BYTE`, unscoped `enum` (`RP_RGBFTYPE`), C++ `enum class` |
| Types (address) | `APTR`, `void *`, `UBYTE *` |
| P96 patterns | `calc_bpr`, `resolve_pixclk`, `set_panning` (boardinfo.h shapes), plus `set_panning_d1` sanity check |

Sources are generated by `gen_probes.py` into `generated/` from the matrix in that script.

## Verification methods

### A. Objdump (recommended / CI)

`check_regparm.py` inspects each probe’s prologue for `move.l dN,d0` / `move.l aN,d0` (or frame-pointer saves) to learn which register supplies the targeted parameter.

Build flags match drivers: `-mregparm=4 -m68020-60 -Ofast -fomit-frame-pointer`, C++ `-std=c++14 -fno-exceptions -fno-rtti`.

### B. Runtime on Amiga (optional)

```sh
make TestRegParm
./../../squirt.sh _bin/TestRegParm SYS:c/
# telnet to Amiga, run: TestRegParm
```

`runtime_main.c` is a **C** caller that invokes C/C++ probes directly and via function pointers (BoardInfo-style). With a fixed g++, enum and `ULONG` cases should PASS.

## a4 / a5 / enum notes

| Case | Expected |
|------|----------|
| **a5** | **SKIP** — GCC frame pointer; `__asm("a5")` reads `sp`. Unusable in hooks. |
| **a4** | Works in these trivial probes; still avoid in production (PIC / reserved). |
| **C + enum + dN** | **OK** — attributes honoured. |
| **C++ + enum / enum class + dN** | **OK** with fixed local g++ (6.5 / 13.2). Unfixed toolchains ignore the attribute (`-Wattributes`) and fall back to `-mregparm` (use `ULONG` / `RGBFTYPE_REG`). |

## Files

## Regenerating after matrix changes

Edit `gen_probes.py`, then:

```sh
make clean && make check
```
